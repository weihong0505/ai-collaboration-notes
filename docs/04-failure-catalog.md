# 失败模式目录

> 来源：作者 41 份项目复盘（约 44 万字符）中的真实事故，按**失败类型**重新归类。
>
> 分类原则：**按"为什么会漏过去"分，不按"哪个项目出的"分。**
> 同一个项目类型上，这十类会反复出现。

---

## 一、静默失败：不报错，但结果是错的

最危险的一类。程序正常退出、测试全绿、日志干净 —— 只有结果是错的。

| 现象 | 真因 | 规则 |
|---|---|---|
| 小程序画布一片空白，**无报错** | 节点只写了 `canvas-id` 没有 `id`，而代码用 `query.select('#id')` 取节点，返回空后**静默 return** | **"没有输出"先查选择器/引用是否真的匹配到了对象** |
| 图表越重绘越坏：纵向缩放第 2 次 1.965、**第 5 次 5.414**，横轴被推出画布外 | `ctx.scale(...)` 与当前变换矩阵**相乘**，旧变换跨绘制复用 → 逐次累乘 | 变换用**绝对设置**（`setTransform`）不用相对累加；**图表类 bug 必须测「重绘 N 次」** |
| 批量文本替换后，三份文档里的 `\|`、`├`、`.` 被换成空格/反斜杠，**脚本报成功** | 嵌套数组 `@{ 'x.md' = @( @('旧','新') ) }` 外层被拍平，`$pair[0]` 退化成**字符串的第一个字符** | 批量替换不用嵌套数组 + 字符串索引；**批量改动前先 commit** |
| 写库失败后，后续所有写入报 `database is locked`，级联扩散 | `insert_*` 无 `try/finally`，异常时 `conn.close()` 不执行，且 traceback 帧持有 `conn` 引用，写锁常驻 | 所有写操作走统一的上下文管理器（成功 commit / 异常 rollback / **finally close**），异常仍上抛不吞 |
| 页面测试**全绿**，但读写全部丢失 | 测试沙箱里假 `wx` 只挂在沙箱对象上，模块顶部的 `createStore()` 由沙箱外执行，`defaultStorage()` 回退成什么都不存的空实现 | **注入依赖的测试基座要能证明注入真的生效**（否则测的是空气） |
| 版本号看着对，跑到某个算子才炸 | 装的包是 CPU 版（`0.26.0+cpu`），与 CUDA 版主包共存；`import` 不报错 | 装完**实测调用一次关键算子**，不是只看版本号 |
| 某加速器件"看起来能跑"却使进程段错误 | 同机同刻另一张同类型图正常 | 进程级段错误 **try/except 抓不到**，必须**进程隔离**并把崩溃记成数据 |

## 二、把"应当等价"当成证据

| 现象 | 真因 | 规则 |
|---|---|---|
| 两批产物的数字对不上，判断"标定只写了温度参数，**应当没问题**" | 把"应当"当证据，无人验证 | 跨来源疑点**不得用"应当等价"驳回**，必须对账**指纹或输出**。实测：46/46、47/47 张量**全部不一致** |
| 两套独立脚本对同一笔费用算出不同结果 | 自己的脚本漏了两个费用科目（差异约 0.5%） | **两套独立算出来的数字对不上，先怀疑自己**；"用于精算的脚本不该有已知缺口" |

## 三、覆盖不全造成假否定（"没测到" ≠ "不存在"）

| 现象 | 真因 | 规则 |
|---|---|---|
| 测了 13 个字段名后下结论"该漏洞不存在" | 漏掉真实字段（藏在压缩 JS 里，需逆向后端契约才能发现） | **先穷尽搜索空间再下否定结论**。枚举**每一个**调用点，而不是凭经验挑几个 |
| 审计报告第一版给出 6 个 FAIL + 28 个 WARN | **全部误报** —— "NPU 不支持动态形状"这句话里含"支持"两字 | 模式匹配要加**上下文窗口 + 否定/纠偏词识别**；中英否定词表兼收并做可配置 |

## 四、自评不可信

撰写者（人或 AI）对自己产出的估计有**系统性偏差**。

| 现象 | 实测 | 规则 |
|---|---|---|
| 英文报告自评"约 5.0–5.5 页" | 独立实测 3,641 词 ≈ **7.28 页**，超官方 6 页硬限 | **篇幅/质量类自评一律用仪器量**（写脚本计数） |
| 文档写"（以上 197 字）" | 脚本实测 **163 字** | **文档里的自述性数字（字数/页数/条数）也必须由脚本产出** |
| 一份长报告声称"测试通过" | 实际只跑了 `--collect-only`（22 collected），**测试体根本没执行** | **审计必须声明证据边界** —— "仅收集未执行"不能称"通过" |

## 五、口径与对照缺失

| 现象 | 真因 | 规则 |
|---|---|---|
| 初稿获奖比例 8.5% / 16.9% / 38.2% | 分母口径未钉死（165 vs 177/179），数字"看起来差不多"就没回算 | **凡"看起来差不多"的数字必须回算** |
| 结论称"某改动同时降低两项指标"，与数字矛盾 | 比较句**缺对照对象**（相对哪个基线？） | **任何比较句必须显式写明对照对象**；审查收口用 **grep 证伪**，不靠目视 |
| 两个口径的收益率被混在一张摘要里 | 测试集口径与训练集口径混用 | **口径不得混用，双口径强制并列**（如 +38.06% 与 +2.07% 必须同时出现在摘要/正文/结论） |
| 回填数据被当成样本外 | 测试集只应评一次；回填数据是 in-sample | **测试集只评一次；回填数据必须标 in-sample** |

## 六、传导漂移：改了源头，交付物没跟上

| 现象 | 真因 | 规则 |
|---|---|---|
| 一个假设被证伪后，**5 份交付物**仍写着旧结论（PPT 第 47 页、英文报告 "on a stronger engine" 等） | 只改了源头文档，靠"我记得改过" | **改了结论 ≠ 改了交付物。** 传导要写成 dry-run 脚本 + 备份 + 逐条打印命中项 + 扫描验证 |
| 传导用的正则**改掉了历史假设的标题** | 同一个词在"设计动作"与"假设名称"两种语境下含义不同，全局替换不辨语境 | **全局替换在记录历史的文档里是危险的**；历史陈述要保留并标注"（原始假设，已证伪）" |
| 同一事故反复四轮 | 没有把"扫描残留"列为固定收尾动作 | 每类改动配一个扫描脚本，并**列为收尾固定项** |

## 七、结构性自伤：编辑动作破坏了文档/代码结构

| 现象 | 真因 | 规则 |
|---|---|---|
| 章节编号跳号（3 直接到 5），**连犯三次** | 整段替换时 `old_string` 含 `## 2.` 标题而 `new_string` 没带回 | **「知道这个坑」不足以防止，只有自动检查可以** —— 写结构检查脚本（标题层级跳级 / 一级编号缺号 / 孤立子节） |
| 全局字符串替换后语义怪异，被审出"表述混乱" | 替换策略过宽，破坏了原文语义 | 替换策略要保守，或改成"检测到即重试" |
| 防回归扫描脚本**误报自己的注释** | 说明注释里照抄了黑名单字符串 | **注释里别照抄黑名单字符串** |
| 守卫做得太狠：夹具缺失时中止整个会话，把本来能跑的 18 条测试也停了 | 只追求"清晰"，牺牲"信息量" | **让失败响亮 ≠ 让流程停摆** —— 改成标记跳过，每条 skip 带原因与修复命令 |

## 八、边界值与退化输入

| 现象 | 真因 | 规则 |
|---|---|---|
| 某窗口参数取 0 时死循环（DoS 级） | 循环条件恒真且缓冲区永不缩减 | 入口处 **fail-fast 校验**参数 > 0 |
| 尺寸为 0 时算出 `Infinity` 并污染画布变换 | `300/0` | 尺寸守卫 |
| 一个自定义校准指标"方向反了" | 先写指标、后验方向：用 `1-\|p-target\|` 当正确性，模型正确预测 0.5 时反被判 +0.5 偏差 | **新指标上线前，必须在已知答案的极端算例上验一次方向** |
| 共识恰为 0.5 的样本被全判正类，**27.3% 样本落在平局带**；准确率 0.90 → 0.77、ECE 0.08 → 0.12 | 0.5 是"不确定"却被当阈值切分，模型正确学到的"不确定"被算成错 | **阈值指标必须先查平局带占比** |
| "还没走到过"的分支第一次执行就报错，废掉一轮 | 该行代码此前从未被执行到 | **「还没走到过」的分支等同于未测试代码，第一次执行就是它的首测** |

## 九、环境与编码

见 [`06-tooling-traps.md`](06-tooling-traps.md)。最典型的三条：

- Windows PowerShell **5.1** 把无 BOM 的 `.ps1` 按 ANSI 解码 → 中文路径乱码 + 解析失败
- `>` 重定向默认写 UTF-16 → 制造**虚假的 `\r\n`**，误判"文件行尾被翻转"
- `python -c` 内联多行 → 引号被 shell 先吃掉（同一错犯过三次）

## 十、把错误信号误读成别的东西

| 现象 | 真因 | 规则 |
|---|---|---|
| 目录移动失败报"被另一进程占用"，但**逐文件试开独占句柄全部成功** | 某进程的**当前工作目录**钉在该目录上；系统不允许改名任何进程的 CWD 或其祖先目录 | **错误信息指向的方向是错的** —— 别继续找文件锁，去查谁的命令行/CWD 指向这个目录 |
| 小文件枚举慢（4 个文件用了 8.4 秒）被判为"整盘要坏" | 慢的是**元数据寻道**（目录里有 6 万多个小文件） | **判断磁盘健康看大文件顺序吞吐**：同一块盘大文件实测 124–126 MB/s = 健康机械盘速率 |
| 硬件告警被当噪音，只顾盯"任务有没有完成" | 事件日志里早已报 IO 重试、设备重置 | **见 IO 重试/设备重置类告警应立即暂停破坏性操作、先排查硬件** |
| 首次推理 58.9 秒，看着像"迁移把性能搞坏了" | 拆解后：从磁盘冷加载占 31.4 秒，推理本身 59.5 tok/s 正常 | **慢要先分解耗时再下结论** |

## 十一、跨项目重复出现的规则（最能说明方法论稳定）

从三份技术栈完全不同的复盘（前端小程序 / Python 教学 / 系统安装）里统计：

| 规则 | 重复次数 |
|---|---|
| **「退出码 0 / 命令返回成功」≠「结果正确」**，必须独立验证或回读 | **3** |
| **平台细节要按平台真实行为写，不凭直觉**（输出流 / 引号 / 编码） | **3** |
| **关键结论区分「已验证」与「存疑」**，未证实的不当结论 | **3** |
| **同一事实只留一个源**，禁止多份拷贝漂移 | **3** |
| **动手前先在只读状态下侦察/备份/快照**，改动留痕 | **3** |
| **收尾必须落四问复盘并同步文档** | **3** |
| **不可逆操作必须加闸门或二次确认，且要测「拒绝路径」** | **2** |

> **结论**：方法论不随项目类型漂移。
> 「先验证再声称、只留一个源、改动可回退、错误路径也要测」这四条，
> 在三个完全不同的技术栈里各自被**真实事故**验证过一次以上。

## 十二、一句话总结

> 这些失败模式的共同点：**它们都不会让你当场发现。**
> 所以规则不是"下次小心"，而是——
> **把每一类曾经出过错的地方，变成一个能自动跑的检查。**
