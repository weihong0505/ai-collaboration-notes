# 工具坑目录：AI 协作里那些「静默给错结果」的地方

> 来源：作者 41 份项目复盘的工具层记录。
> 收录标准：**失败是静默的，或错误信息指向错误的方向** —— 这类坑最难自查，也最值得写下来。
>
> 长文版散落在 [quant-investing](https://github.com/weihong0505/quant-investing) 的
> `wiki/entities/system/ai-tools/` 下（6 页），本文是跨项目的合并与提炼。

## 一、Windows / PowerShell —— 重灾区

| 坑 | 现象 | 真因 | 规避 |
|---|---|---|---|
| **无 BOM 的 `.ps1` 被按 ANSI(GBK) 读** | 中文字面量路径变成乱码（连分隔符都被吞），日志写进乱码目录；脚本报一堆 `Unexpected token` | Windows PowerShell **5.1**（非 pwsh 7）对无 BOM 的 `.ps1` 用系统 ANSI 代码页解码 | 含中文的 `.ps1` **必须存成 UTF-8 带 BOM**；或脚本 100% ASCII，路径从 `$PSScriptRoot` 运行时推导 |
| **`>` 重定向默认写 UTF-16** | 行尾/编码类检查出现**虚假的 `\r\n`**，被误判为"文件行尾被翻转" | PowerShell `>` 以 UTF-16 落盘，再按 UTF-8 解码即产生假 CRLF | 行尾/编码类断言**必须用 `git hash-object` 逐字节比对**，不能用经过 PowerShell 重定向或管道的读数 |
| **`$ErrorActionPreference='Stop'` + 原生命令写 stderr** | 脚本在无关步骤中断（如 git 的 LF/CRLF 警告） | PS 把原生命令的 stderr 输出当成终止性错误 | 调用外部命令前后局部切 `'Continue'`，用 `2>&1 \| Out-Null` + 查 `$LASTEXITCODE` |
| **`python -c` 内联多行** | `SyntaxError: unterminated string literal`；传中文会损坏 | `"`、`$` 被 PowerShell 先解析掉 | **含中文或多行的脚本一律先落盘再执行**（同一错犯过三次，第三次后才成为纪律） |
| **`WshShell.CurrentDirectory` 不接受非 ASCII 路径** | 进程起不来，**无报错、无输出** | 该属性本身不支持非 ASCII；且失败时 `wscript.exe` 弹**隐藏模态框**，只查 `Get-Process` 的 `MainWindowTitle` 才看得见 | 不用 VBScript 做启动器，改用**计划任务**（原生 Unicode 路径支持） |
| **不支持 heredoc** | 长脚本拼装困难 | — | 落盘再执行 |
| **`Move-Item` 报"被另一进程占用"，但逐文件试开独占句柄全部成功** | 看起来根本没有锁 | 某进程的**当前工作目录**钉在该目录上，系统不允许改名任何进程的 CWD **或其祖先目录** | 别继续找文件锁 —— **去查谁的命令行/CWD 指向这个目录**（`Get-CimInstance Win32_Process` 看 `CommandLine`）。CWD 占用是**目录级**的，逐文件检测天然看不见 |

> 上表最后一条是本目录里最有价值的一条：**错误信息（"文件被占用"）指向的方向是错的**，
> 按它排查会一直找不到原因。

## 二、AI / 推理工具链

| 坑 | 现象 | 规避 |
|---|---|---|
| **OpenAI 兼容端点丢 `tools` 字段** | 模型不产生工具调用，看起来像"模型不会用工具" | 换端点或直连原生 API；把它当成已知缺陷而不是模型能力问题 |
| **SDK 装成 CPU 版** | `import` 正常，只在跑到某个算子时才炸；版本号看着对 | 装完**实测调用一次关键算子**，不是只看版本号 |
| **`--system-site-packages` 造成同包双版本** | pip 报依赖冲突并返回退出码 1，但包实际装成功了 | **退出码 1 在此不代表安装失败** —— 看实际状态 |
| **NPU 只接受静态形状** | 动态 `[?,?]` 图直接编译失败；INT8 量化在 NPU 上是**负优化**（比 fp32 慢 2×） | 静态形状是 NPU 可编译的**前提**，不是优化选项；先量再选设备 |
| **NPU 数值精度约 1e-2** | 同样的图在 CPU 上误差 3e-6，在 NPU 上 0.024 | 对 argmax 无影响；别指望它做需要高精度的数值计算 |
| **某加速器件"看起来能跑"但会段错误** | 同机同刻另一张同类型图却正常 | 只有实测能发现；把失败结果**留在报告里**而不是删掉 |

## 三、多智能体（Agent）协作

| 坑 | 现象 | 规避 |
|---|---|---|
| **子代理不能再分派** | 返回 `depth 2 exceeds maxDepth 1` | 派活时要么不假设它能再分派，要么在任务书里写明「不可再分派，用并发替代」 |
| **常驻子代理会唤醒父代理** | 父代理被一条 settlement 通知意外激活 | 知道这个机制存在；不要用"让它静静跑"来假设父代理不被打断 |
| **只盯"已启动"会漏掉静默失败** | 4 个并行评审里 1 个首跑**无产出、无说明** | 派活后**必须盯产出落盘** |
| **宽范围委派会空转** | 某次资产审计执行者空转 12 分钟零交付 | 委派要设**明显的收敛条件**；换人 + 收紧范围后成功 |
| **撰写者对自己篇幅的自评有系统性偏差** | 自评"约 5.0–5.5 页"，独立实测 3,641 词 ≈ **7.28 页**，超官方 6 页硬限 | **篇幅/质量类自评一律用仪器量**（写脚本计数），不信自述 |
| **合成数据过关 ≠ 方法成立** | 曾据合成数据的正向结论（+0.024~+0.039）当开工理由；真实样本上改善 **−0.0272（方向相反）**，后续 6/6 配置全输 | 合成自测只验证"代码路径能跑通"，**不构成"方法更优"的证据** |
| **AI 写的长技术文档，最该查的是技术陈述准确性** | 子代理反向挖出主控 v0.1 的 10 处缺陷 | 对 AI 长文做**负向模式匹配 + 否定/纠偏豁免**，比正向穷举可靠；并配负向测试 |

## 四、网络与抓取

| 坑 | 现象 | 规避 |
|---|---|---|
| **本机 DNS 是 fake-IP 模式** | 所有域名解析到 `198.18.x.x`；抓取工具以"non-public IP"拒绝 | 用本机脚本抓取（落盘再读），不要依赖内置抓取工具 |
| **`HTTP 200` ≠ 拿到数据** | 返回 200 但正文是 GBK 乱码、或 JS 壳页、或空表格 | **必须看正文是否有实际内容** |
| **全站 WAF 412，但静态文件直链可通** | 网页全站 412，PDF 和静态数据目录直链正常 | 绕开网页层直接取静态资源 |
| **PDF 返回 `unsupported content type`** | 抓取工具拒绝 | 改用官方网页版取得同等内容（常更权威）；或本地解析 |
| **`Invoke-RestMethod` 不跟随 308 重定向** | 拿不到内容 | 改用 `curl.exe -sL` |
| **同花顺移动页 200 但解码为 GBK 乱码，工具不报错** | 看起来"只是乱码" | 优先找**带历史数据表格的静态页**，而不是行情图页 |

## 五、git

| 坑 | 现象 | 规避 |
|---|---|---|
| **`git add -A` 带进别人的未提交改动** | 提交里混入了不是自己产生的约 138 行 | `git add -A` 前先 `git status`；带了别人的东西，**必须在提交信息里说清**（或 `--amend` 披露） |
| **行尾/编码断言被工具污染** | 误判 14 个文件"行尾被翻转" | 用 `git hash-object` 逐字节比对；尺寸自洽也能反证（447 B 增量 = 路径字符串变长 × 出现次数） |
| **导出/发布时忘记大件** | 某库 20 GB 模型目录**未被忽略**，`git add -A` 会灌进 8.6 MB 仓库 | 迁移/发布前先核对 `.gitignore` 覆盖；用「`目录/*`」而不是「`目录/`」（后者连目录内 README 一起排除，且 git 无法重新包含被排除目录下的文件） |

## 六、PDF 与生成类交付物

| 坑 | 现象 | 规避 |
|---|---|---|
| **PDF 表格不能信纯文本流** | `find_tables()` 仍出现表头空列；某些附件文本层 **0 字符**（纯扫描件） | **坐标重建 + 渲染成图片人工逐页复核** |
| **生成类交付物（PPT/图/网页）不渲染就等于没检查** | 导出 19 张 PNG 复核时，才抓到封面印着"封面"两个字、顶部色带是空的 —— 而二者**结构核验均通过** | **生成类交付物必须渲染出来用眼睛看** |
| **结构检查脚本查不出内容错误，内容检查查不出结构错误** | 整段替换时 `old_string` 含 `## 2.` 标题而 `new_string` 没带回，章节编号跳号（**连犯三次**） | 写结构检查脚本（抓标题层级跳级 / 一级编号缺号 / 孤立子节）；**「知道这个坑」不足以防止，只有自动检查可以** |

## 七、一句话总结

> 这个目录里的每一条，**失败都是静默的，或者错误信息指向错误的方向**。
> 所以规则不是"下次小心"，而是：**给每一类曾经出过错的地方配一个脚本。**
>
> 作者的实际做法是「防自欺工具链」—— 截至某项目复盘时已有 **7 个脚本，
> 每一个都对应一次真实失误**（字数计量 / 提交前检查 / 文档结构 / 标注一致性 /
> 复现清单 / PPT 生成 / 事实核查）。
