# 多智能体审计流水线

> 来源：作者 41 份项目复盘。本文专门讲**如何组织多个 AI 代理去审计一份交付物**，
> 以及审计过程中最容易被忽略的三件事：证据分级、审查锚点、复验闭合。
>
> 与 [`02-adversarial-review.md`](02-adversarial-review.md) 的分工：
> 02 讲"要不要审、怎么审出真问题"；本文讲"**一次审计怎么组织、怎么收口**"。

---

## 一、三层审查层级

一次完整审计不是"派一个 agent 看一眼"，而是三层：

| 层 | 执行者 | 做什么 | 产出 |
|---|---|---|---|
| **L1 · 作者自检** | 交付者本人 | 结构与内部一致性：数字对得上吗？行数对吗？重算残差为 0 吗？ | 自检记录 |
| **L2 · 独立 / 交叉审查** | 另起上下文的代理 | 不见实现思路，从攻击面出发找问题 | 发现项列表 |
| **L3 · 复验** | 第三轮 | 对每条发现项**回到一手产物**验证是否真的修掉了 | **「ID ｜ 状态 ｜ 证据」复验表** |

**为什么必须分成三层**：L1 只能发现"和我预期不符"的问题；
L2 能发现"作者想不到"的问题；L3 防止"改了个说法但数字没动"。

L3 的复验表长这样（真实格式）：

```
| ID    | 状态   | 证据                                        |
|-------|--------|---------------------------------------------|
| E-M1  | 已消除 | 正文已无「全 0.0%」表述                      |
| E-M2  | 已写   | 逐情景回填，最大 0.72%（对齐 class_change_rate_max） |
| E-M3  | 无泄漏 | 附录未出现外部数据                            |
| E-S1  | 已消除 | in-sample 已显式标注                         |
```

> **关键：复验要回到一手产物，不能只看改写后的文字。**
> 例：确认某个数字已经改正，不是去读文档里那句话，而是去读
> 底层 JSON 里的字段值（如 `class_change_rate_max = 0.00718455`）。

## 二、冻结锚点：防"边审边改"

这是多智能体审计里**最容易毁掉整次审计**的问题。

**规则：主结论数字必须先冻结，审查期间只允许改表述与附录。**

具体做法：
- 审查期声明「**未重跑已成功的大计算**」—— 重跑会引入新变量，让审查结论失去参照
- 原始结果文件**一律不覆盖**，重跑写到 `rerun/` 子目录
- 结论产物（论文 docx）从**唯一的 md 源头生成**，而不是手改 docx
- 官方结果文件的时间戳保持不动（证明没被改写）

> **为什么**：审查员复核的是某一时刻的产物。
> 如果作者在审查期间并行修改，审查员的算术复核可能指向一个**已不存在的对象** ——
> 结论作废，审查白做。（这件事真实发生过一次，见 [02](02-adversarial-review.md) §四）

## 三、证据分级：FACT / INFERRED / UNCONFIRMED

派活时就**向子代理下发证据等级要求**，而不是让它自由发挥。

| 等级 | 含义 | 例子 |
|---|---|---|
| **FACT** | 有直接观测支撑 | 响应体的 SHA-256 逐字节比对结果 |
| **INFERRED** | 从已知行为推断，未直接观测 | 某库的默认参数行为（文档未明说） |
| **UNCONFIRMED** | 无法验证，只能标注 | 某端点的响应结构（不能实际调用） |

**配套规则**：
- **只读任务不越界** —— 任务书写明"不实际调用任何端点"，就不要为了拿证据而调用
- **任务书与安全规则冲突时，换"等证据等级"的手段** ——
  例：想探测错误 HTTP 方法，但规则禁止；改用另一个自身返回 405 的正常端点达到同等验证目的
- **结论必须可复推** —— 每处摘录标注**字节偏移**，审计者可凭原始文件重推

## 四、发现项要编号、分级、闭环

**格式**：`<题号>-M<n>`（must-fix）/ `<题号>-S<n>`（should-fix）。

**为什么要编号**：
- 让"这条改没改"变成可追踪的状态，而不是靠记忆
- 复验表可以逐条打勾，形成闭合
- 审查员与作者可以引用同一个 ID，不产生歧义

**收口用 grep 证伪，不靠目视**：
例：要确认"正文里已无无对照的比较句"，不是通读一遍，而是
**写一条 grep 去搜那种句式，搜不到才算过。**

## 五、负面结果必须同等对待

**反面**：只报"发现了 N 个问题"，把"没发现问题的部分"省略。
**做法**：报告里把**干净否定**也列出来。

真实例子：一份审计报告列了 **11 条问题 + 13 项干净否定**，并写明
某条结论判为 **NOT REPRODUCED**，依据是哈希值本身。

> **为什么**：只报问题的报告无法回答"你查了多大范围"。
> 13 项干净否定 = 审计覆盖了 24 个点，而不是 11 个。

## 六、定量分析的专用纪律

当审计对象是**有数字的建模交付物**时，额外几条：

| 纪律 | 说明 |
|---|---|
| **口径不得混用，双口径强制并列** | 两个口径的收益（如 +38.06% 与 +2.07%）必须**同时**出现在摘要/正文/结论，不能只报好看的那个 |
| **测试集只评一次；回填数据必须标 in-sample** | 用测试集调参 = 结果作废 |
| **稳健性实验中策略与质量函数全冻结** | 否则不同随机实例的分位不可比 |
| **随机化要真改结构，不能只重排标签** | 同构置换**无信息量** —— 必须在可行域内重采样真正的自由变量 |
| **官方实例解与随机分布分开存放、分开表述** | 外推句必须带分布，或明确标注"本附件实例" |
| **关键数值锚点要多求解器对账** | 同一条结论用 4 个不同求解器算，结果必须一致（某项目锚点 `35126.948589`，四路一致） |
| **验收用硬校验，不用库的便利属性** | 某库的"最大行数"属性会受文件 dimension 影响偏小 → 改用显式扫描 |

## 七、把"改一次就悄悄坏掉"的约束写成测试

这是多智能体审计留下的**最有价值的副产品**。

一旦某类错误出现过一次，就写一条自动测试让它不可能再犯。真实例子：

- `test_no_hardcoded_drive_paths_in_src` —— 用 AST 扫描源码，禁止出现写死的盘符（守住 8 处历史违规点）
- `test_run_ps1_has_utf8_bom` —— 检查脚本是否有 UTF-8 BOM（Windows PowerShell 5.1 的编码坑）

**为什么用测试而不是文档**：
> 「知道这个坑」不足以防止 —— 有的坑在**明知的情况下又踩了一次**。
> 只有自动检查可以。

## 八、长任务的工程卫生

| 做法 | 原因 |
|---|---|
| **中间落盘** | 长跑脚本每 N 个实例写一次结果文件，崩溃不用从头再来 |
| **会崩的调用隔离到子进程** | 进程级段错误 `try/except` 抓不到；隔离后把崩溃记成结构化数据，其余部分继续跑完 |
| **审计声明证据边界** | 只跑了"收集"就写"仅收集未执行"，不能称"通过" |
| **批量替换不用嵌套数组 + 字符串索引** | 单元素外层数组会被拍平，索引退化成"字符串的第一个字符"，**不报错照跑成功** |
| **批量改动前先 commit** | 出问题一条 `git checkout HEAD --` 就能全量复原 |

## 九、一份可复制的审计组织清单

**派活前**
- [ ] 子任务**按产物切分**，不按流程步骤切
- [ ] 任务书里写明**证据等级要求**（FACT/INFERRED/UNCONFIRMED）
- [ ] 任务书里写明**边界**（只读？不得调用？不得外推？）
- [ ] 主结论数字**已冻结**，原始结果文件不可覆盖
- [ ] 宽范围委派设了**明显的收敛条件**

**审计中**
- [ ] 每个子代理交付**四段式复盘**（做了什么 / 关键决策 / 教训坑 / 交付）
- [ ] 发现项**编号 + 分级**（must-fix / should-fix）
- [ ] 负面结果（干净否定）**同等记录**
- [ ] 外部下载物先与官方 **SHA-256 校验**一致才执行

**收口**
- [ ] L3 **复验表**逐条给出「ID ｜ 状态 ｜ 证据」
- [ ] 复验**回到一手产物**，不看改写后的文字
- [ ] 关键改动配 **grep / 脚本** 证伪，不靠目视
- [ ] 审计结论**声明证据边界**
- [ ] 新出现的错误类型 → **写成自动测试**
- [ ] 审计过程本身的失败（如边审边改）**也记入复盘**

---

## 十、一句话总结

> 多智能体审计的价值不在于"多派几个人"，
> 而在于**三层结构 + 冻结锚点 + 复验闭合**这三件事同时做到。
> 少了任何一件，审计都会变成"看起来审过了"。
